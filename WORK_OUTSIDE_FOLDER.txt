1. Claude's private cloud sandbox (Anthropic-hosted Linux session workspace, deleted when the session ends)
   Why: your PC's Linux shell (used by Claude to edit this folder) has no internet and cannot run the
   Windows .exe tools, so automated emulator screenshots and headless Godot runs happen in the sandbox.
   What was put there:
     - a copy of the ROM and .sav from baseroms/ (for melonDS reference captures; never shared anywhere)
     - Godot 4.7.2 Linux build   (github.com/godotengine/godot release 4.7.2-stable, same version as tools/)
     - melonDS 1.1 Linux AppImage (github.com/melonDS-emu/melonDS release 1.1, same version as tools/)
     - a tiny libOpenGL.so.0 shim (links to the system libGL) so the melonDS AppImage starts under Xvfb
     - melonDS savestates (rom.ml1..ml4: mode select, character select, stage select, battle start)
   Everything produced there that matters (scripts, notes, reference screenshots, converted assets)
   is copied back into this folder.

2. melonDS on Windows (tools/melonDS-1.1-windows-x86_64)
   melonDS keeps its config (melonDS.toml) next to melonDS.exe, inside this folder. Nothing outside.
   NOTE: melonDS writes in-game saves next to the ROM, i.e. baseroms/*.sav (your existing save file).

3. Godot on Windows
   The Godot editor stores editor settings in %APPDATA%\Godot\ and the game's user:// data in
   %APPDATA%\Godot\app_userdata\<project name>\ . That is standard Godot behaviour, outside this folder.
   The project is configured with a custom user dir name "DBZSSW2Port" so it is easy to find/delete.
